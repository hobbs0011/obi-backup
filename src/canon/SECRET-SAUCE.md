## §1 · THE BEST PRACTICES — the foundation

Enforce these **in code** before reading §2. A practice you have not automated is a preference.

| id | the practice | why it is load-bearing |
|---|---|---|
| **BP-01** | **Measure, never assume.** | A number or a refusal — never a guess. Every claim in this station's delivery pipeline is a fetch that answered, or a door quoted refusing. |
| **BP-02** | **Fail closed, and say why.** | When the check cannot run, the answer is *no*, with the reason. A gate that "probably" worked is a gate that is open. |
| **BP-03** | **Never report COMPLETE over a hollow stage.** | A shut door gives HELD; a hollow stage gives GAP. Smoothing the two into a success is a lie, and it is the lie every pipeline eventually tells. |
| **BP-04** | **Append, never rewrite.** | Logs, registers and doctrine grow. A rewrite destroys the evidence that the earlier reading was wrong — the most valuable thing in the whole record. |
| **BP-05** | **One list is the authority.** | A file that is not in the declared list is not in the backup, the census or the delivery. Two lists drift; one list cannot. |
| **BP-06** | **Address content, not names.** | Hash the bytes, deliver by digest. Identical bytes return the identical URL. Re-uploading what you already have is how a system starts lying about what changed. |
| **BP-07** | **Verify by re-fetching, not by asserting.** | After delivering, pull every URL back and re-hash it. "The delivery happened" is a measurement taken afterwards, never a claim made before. |
| **BP-08** | **Name the gap out loud.** | Every register, scan and report carries a section for what it could *not* do, with the reason. What is unstated is what is discovered later as a defect. |
| **BP-09** | **The source is the product.** | On a platform that publishes your source by existing, the tree *is* the deliverable. Tidy it, register it — and it becomes the marketing for free. |
| **BP-10** | **Ship the artefact, not the explanation.** | A README that works, a register with real digests, a corpus with a hash — these travel. Prose about what you *would* build travels nowhere. |

## §2 · THE BEST-KEPT SECRETS — the upgrade

Read these **against §1, never before it**. That ordering is the secret.

**SEC-01 · The empty seat beats the crowded market.** 3,216 repositories fighting over "ai website builder" is a marketing-budget war. 271 repositories with a 69-star leader and **no index at all** is an unclaimed seat. The cheapest seat in any market is the one nobody sat in.

**SEC-02 · Give the method away; the offer converts.** Best practices cost nothing to give and are the only thing that travels in a young market. The work at the end of them — a built website, a done-for-you system — is what is paid for. **The method earns attention; the offer earns money.** Attention without an offer is applause.

**SEC-03 · Your target is a number you can read.** The field's leader is 69 stars. That is a scoreboard, not a metaphor. One system-tier repository in a field of wrappers passes it — and the day it does, `/market` prints it.

**SEC-04 · A dead package registry is an open one.** Seven packages and 18 downloads a week reads as failure only if you wanted traction. Read correctly, it is an **uncontested namespace**. Ship scoped, not bare: the bare name is taken.

**SEC-05 · Train on your own canon, best practice first.** *This is the intelligence lane, and it is the one thing here a competitor cannot copy quickly.* Assemble the corpus from what is already true — the practices your own system enforces, **then** the measured facts, **then** the secrets. **Order is the point:** a model fed secrets first learns to guess; a model fed the practices first learns to check, and then reads the secrets against a frame that does not hallucinate. This station cannot fine-tune a model and says so — what it *can* do is produce the ordered, de-duplicated, measured corpus that a training run or a retrieval index actually consumes, with a digest proving it did not change under you. `/SecretSauce train` builds it.

**SEC-06 · Publish your refusals.** Every honest system has doors it cannot open — the anti-bot write that will not pass, the missing credential, the forum endpoint returning **403**. Most projects hide them. Publishing them, with the door's own words, is the cheapest credibility available, because nobody else in the field does it. A printed refusal is evidence you did not fake the passes.

**SEC-07 · The name is not the brand; the method is.** 731 Hacker News hits for "perchance" and not one about the platform; zero dev.to articles about the field. Do not fight a drowned name — publish under a **method's** name and let the method be what people search for.

**SEC-08 · Make the index, and every future project files itself under you.** An index is the only artefact in open source that grows without you: every new project must choose which list to open its pull request against, and there is only one list. You are not asking to be linked. You are becoming the place the links go.
